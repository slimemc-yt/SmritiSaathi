# AI-Based Cognitive Gaming and Memory Assistance Platform for Elderly Dementia Patients in NER
### Full Product Specification + Claude Code Build Plan

**Stack locked in:** Native Android (Kotlin/Jetpack Compose) + Native iOS (Swift/SwiftUI) + Firebase (Spark/free tier) backend + Google Gemini API (free tier) for AI + Bhashini API (free) for NER regional voice, with on-device TTS/STT fallback + Wear OS (free) smartwatch companion.
**Build order:** Firebase backend → Android app (full) → iOS app (full) → Wear OS companion → Integration & polish.

---

## PART 1 — THE THREE ACCOUNTS

The app asks **"Are you a Patient, Family Member, or Doctor/Health Worker?"** on first launch, right after language selection. Each role gets a completely different app experience, but they all connect through the same patient record in Firebase.

### 1.1 PATIENT Account

**Purpose:** the patient almost never actively "uses" this like a normal app user — the app reaches out to them.

**Login & Device Pairing:**
- **Zero-Password Setup**: The patient device is provisioned via a 6-digit Device Pairing Code (e.g. `842-913`) generated by the Family Member during onboarding.
- The patient device authenticates anonymously via Firebase Auth (`signInAnonymously`) and stores the bound `patientId` permanently in Android `DataStore`.
- After setup, patient **never logs in again**. The app stays signed in permanently on that one device. No PINs, no passwords, ever, for the patient.

**Onboarding (done by family member, on the patient's behalf):**
- Patient's basic details: name, age, gender, photo/avatar, preferred language, dementia stage (Mild / Moderate / Severe — this sets the Tier, see Part 3)
- Medical reports: photo/document upload of prescriptions, diagnosis papers, past reports
- Family contact details: name, relationship, phone number, photo/avatar of each family member (used later for face-recognition game and "who's calling" cues)
- Assigned doctor / local hospital / health worker (searchable list, or manual entry if hospital not listed — important for NER since not every hospital will be in a directory)
- Daily routine static inputs: wake time, nap times (customizable, since elderly nap patterns vary day to day), meal times, medicine times, sleep time
- Emergency contact + one-tap SOS number (this can literally be "call this number" — no complex logic needed)

**What the Patient actually sees/does (all tiers):**
- **No home screen with app icons.** The patient's phone, once set up, opens directly into this app's "Today" screen or the app auto-launches at scheduled moments.
- **One task at a time, full-screen, big fonts, minimal text, voice-first.** Never more than one primary action button visible.
- A running "Today" view showing only the *next* thing to do (not a to-do list — a to-do list is confusing/overwhelming). Example: a full screen says "Good morning, Hemlata 🌞" with one big button "Start your 10-minute activity."
- Games (see Part 4 — full game list from your team's game doc)
- Reminiscence corner: family photos + voice notes, "guess who's speaking," memory of childhood/school/marriage/family life stages
- Medication & Routine Assistant: voice announcement + 3 buttons only — **Taken ✅ / Remind me later ⏰ / I need help 🆘**
- Quick daily check-in: "What did you eat today?" style regular-interval simple questions (used for both engagement and behavioral-change detection)
- SOS button always reachable within one tap from anywhere in the app
- Grandchildren/family "Play with me" game invites — arrive as a big, friendly "🎮 Aarav wants to play a game with you!" prompt, not a generic notification
- Simple voice assistant: "What day is it?", "Who is this?" (pointing camera at a person), "What did I eat today?"

### 1.2 FAMILY MEMBER Account

**Purpose:** command center + emotional connection layer. Multiple family members can be linked to one patient (siblings, spouse, grandchildren all get their own logins under the same patient profile).

**Login:** Google Sign-In via Firebase Auth (100% Free on Spark plan, zero SMS cost, standard mobile UX).

**Features:**
- **Full analytics dashboard**: cognitive score trend graphs (daily/weekly/monthly/yearly), game-by-game performance, reminder adherence %, mood/engagement trend, sleep/nap pattern logs
- **Behavioral Change Alerts**: automatic flags when performance drops suddenly, when routine deviates (e.g., patient hasn't opened the app in X hours, skipped 2+ meals, repeated wrong answers pattern) — pushed as gentle, non-alarming notifications with context ("Dad's game scores have been lower than usual this week — might be worth a check-in call")
- **Remote controls:**
  - "Start Dad's Game Now" button — force-triggers a task on the patient's phone instantly via Firestore `/pendingActions`
  - "Send a Nudge" — push a friendly voice reminder to the patient's phone
  - Upload photos/voice notes for the reminiscence module
  - Set up/edit daily routine, nap times, reminders remotely
  - Add/edit family contact photos for the face-recognition game
- **"Play with Grandpa" feature**: any linked family member (especially grandchildren, on their own login) can send a simple game invite that shows up specially on the patient's screen
- **Companion access mode** (per Aryan's suggestion in the chat): family members can optionally "join" a game session remotely — e.g., video/voice-assisted trivia sessions, so it doubles as a bonding activity, not just monitoring
- **Report sharing**: auto-generated weekly/monthly/yearly PDF reports, shareable directly to the assigned doctor
- **Emergency alerts inbox**: instantly notified if patient taps SOS or presses "I need help" on a medication reminder
- **Multi-family-member permission levels** (optional, Tier-based): e.g., primary caregiver can edit everything, other family members can only view + send game invites/nudges

### 1.3 DOCTOR / HEALTH WORKER Account

**Purpose:** clinical oversight without needing the doctor to be constantly active — designed for NER's low doctor-to-patient ratio, works with ASHA workers/NHM network too.

**Login:** Google Sign-In via Firebase Auth, verified against doctor profile code (e.g. `DOC-8821`).

**Features:**
- View **read-only** cognitive trend data, game performance, and auto-generated reports for every patient assigned to them
- Add clinical notes/observations tied to a patient's timeline
- Adjust the AI's task-selection parameters within safe bounds (e.g., mark certain cognitive domains as priority for a specific patient based on real diagnosis)
- Push official guidance to the family member's app (e.g., "Please ensure patient takes medicine X strictly at 8 AM")
- See flagged Behavioral Change Alerts across **all** their patients in one triage-style list, sorted by severity/recency — built for a doctor covering many patients across a district
- Telemedicine tie-in placeholder: "Schedule a call" button that opens a simple video-call flow with the family member's app
- Multi-patient view, since one doctor/ASHA worker will be attached to many patients across a region

## PART 2 — SOLVING "THE PATIENT FORGETS THE APP EXISTS" (core design pillar)

This is treated as the **default state**, not an edge case, across the whole app:

1. **The app never asks the patient to "open" it.** It comes to them.
2. **Trigger model:** When the patient unlocks/opens their phone (any time, for any reason — even to check the time), the app intercepts and shows whatever the *next scheduled task* is, styled like an **incoming phone call** ("📞 Reminder call from Wellness App — Tap to answer"). This mirrors the most universally understood interaction pattern for elderly first-time smartphone users, and it was specifically chosen over a silent notification because notifications get mistaken for ads/spam.
3. **Scheduled interval tasks**, not a to-do list — one task appears at a time, at set intervals through the patient's active hours (informed by their nap-time static inputs, so we don't interrupt sleep).
4. **No sound-based "the app is being ignored" alarm** by default — the team explicitly rejected a randomly-ringing alert (could go off during sleep/naps and cause distress). Instead: check on phone-open only.
5. **Zero working memory required**: every screen is self-contained, one action, persistent on-screen instruction, no multi-step navigation.
6. **Idle/no-response handling**: if the patient doesn't respond to a task, gently re-prompt via voice once, then softly exit to the calm Today screen — no error, no guilt messaging.
7. **Distress/confusion detection**: rapid erratic taps or repeated wrong answers switch the screen to a calming reminiscence clip (familiar photo + family voice message) instead of continuing the task.
8. **Caregiver safety net**: if the patient hasn't interacted at all for an unusual period, the family member gets a check-in alert — this is the ultimate fallback for "what if they forget completely."

## PART 3 — TIERED SEVERITY MODES (set once during onboarding, editable by family/doctor)

| Feature | Tier 1 — Mild | Tier 2 — Moderate | Tier 3 — Severe |
|---|---|---|---|
| Navigation | Full simple menu | Single-task-at-a-time, no menu | Auto-launch only, zero navigation |
| Reminders | In-app + call-style prompt | Call-style prompt, repeats once if ignored | Forced full-screen takeover, repeats with voice |
| Lock/Home screen | Untouched | Optional overlay for reminders | **Kiosk mode**: app takes over home & lock screen entirely (Android Screen Pinning / iOS Guided Access) — explicit opt-in permission required from family during setup |
| Input | Touch | Touch + voice | Voice-first, minimal touch, larger targets |
| Distress/calming mode | Off | Manually triggerable by patient (a "I'm confused" button) | Automatic on erratic input detection |
| Family remote trigger | Optional | Recommended, on | Essential, on by default |
| Find-my-phone sound | Off | Optional | On |

**Important for the pitch:** Tier 3's kiosk/lock-screen takeover is explicitly consent-based (family enables it during onboarding), never a silent default — ethical, non-invasive design.

## PART 4 — GAMES & COGNITIVE MODULES (from the team's game document)

1. **Face Recognition Game** — family members, basic animals, celebrities the patient likes (family uploads these)
2. **Card Games** — simple matching/memory card games
3. **Daily Routine Game** — arrange the patient's own daily routine steps in correct order
4. **NER Familiar-Images Game** — shows region-relevant images (state-wise: Kaziranga/Bihu for Assam, Tawang/Losar for Arunachal, Living Root Bridges for Meghalaya, Hornbill Festival for Nagaland, Loktak Lake/Sangai deer for Manipur, Bamboo dance for Mizoram, Kharchi Puja for Tripura, Gangtok/Losar for Sikkim) with follow-up questions tied to whichever state is relevant to the patient
5. **Shopping Basket Challenge** — show a short shopping list visually (e.g., 🥛 Milk, 🍌 Banana, 🍚 Rice), hide it, show many objects, ask patient to pick the correct items
6. **Quick Recall Game** — display a short statement ("Sai wore a red dress on Tuesday to school"), then ask follow-up questions (What colour? Which day? To where?)
7. **Life-Stage Memory Game** — reminiscence prompts structured across Childhood → School → First Job → Marriage → Family → Present Day
8. **Guess Who's Speaking** — family-recorded voice clips, patient identifies who's speaking (optional, only if family sets it up)
9. **Music/Song Memory Game** — plays familiar old songs relevant to the patient's era/region as a memory + mood-lifting trigger
10. **Medication & Routine Assistant** (functions as both a reminder and a light interaction): voice announcement → Taken ✅ / Remind me later ⏰ / I need help 🆘 → instant caretaker alert if not marked done by expected time

**Difficulty progression (AI-controlled, patient never picks a level):**
- Level 1: remember 2 items
- Level 2: remember 3 items
- Level 3: remember 5 items
- The AI decides what the patient sees next — the patient never navigates a menu to choose a game.

**Every game must have:** voice instructions in the patient's selected regional language, on-screen text as a secondary aid (for those who prefer reading), and a sound/audio icon control per game.

## PART 5 — NER-SPECIFIC HANDLING (built in, not an afterthought)

- **Languages:** Assamese, Bodo, Khasi, Garo, Mizo, Manipuri (Meitei), Nagamese, Hindi, English — selected once at first setup, used for every voice prompt, instruction, and on-screen label app-wide
- **Voice engine:** Bhashini API (free, Govt of India, built specifically for Indian regional languages) as primary; on-device native TTS/STT as automatic fallback if Bhashini is unreachable (handles patchy connectivity)
- **Offline-first:** all core patient-facing features (games, reminders, reminiscence content, medication assistant) work fully offline using locally cached data; sync to Firebase happens automatically whenever connectivity returns. Only things that strictly require internet: live AI chatbot Q&A, telemedicine calls, and initial content sync
- **Low-end device support:** lightweight builds, minimal background battery/data drain (since this is very likely the household's only shared phone)
- **Cultural content:** state-relevant games/images (see Part 4, item 4) instead of generic Western content, to improve both recall accuracy and emotional engagement
- **Health infrastructure tie-in:** doctor/ASHA-worker account type designed around NER's actual low specialist-availability reality, with district hospital directory + manual entry fallback for hospitals not in the system

## PART 6 — CROSS-CUTTING NON-FUNCTIONAL REQUIREMENTS

- **Accessibility:** large fonts, high contrast, adjustable voice playback speed, large touch targets (for tremors), swipe gestures preferred over precise tapping, minimal text/maximum visuals
- **Privacy/security:** DPDP Act 2023-aligned consent flow during onboarding, encrypted storage of medical reports and personal data in Firebase, explicit consent screen before enabling any Tier 3 kiosk/lock-screen permission
- **No diagnosis claims:** app is clearly positioned everywhere (onboarding, about screen, reports sent to doctors) as a support/monitoring tool, not a diagnostic tool — always recommends professional consultation
- **No guilt-based UX:** no "you failed," no streaks, no penalty for abandoning a task mid-way
- **Free-tier only:** Firebase Spark plan, Gemini API free tier, Bhashini free tier, no paid Apple Developer account required for the Android/Wear OS build path (iOS build documented but will need a developer account only at final App Store submission stage, not during development)

### STEP 1 — Cloud Functions for Core Logic
```

Keep everything within Firebase's free Spark plan quotas where possible; flag anywhere this 
isn't fully achievable (e.g., Cloud Scheduler minimum requirements) with a clear free-tier 
workaround (e.g., trigger the overdue-check from the patient app itself on each app-open
```
